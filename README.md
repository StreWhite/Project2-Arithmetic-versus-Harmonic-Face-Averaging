# MTH321 Project 2: Variable Diffusion

This project studies a conservative finite-difference discretisation of

```text
-div(a grad u) = f  in (0,1)^2,
u = g              on the boundary.
```

The experiments reproduce five evidence chains:

1. a smooth manufactured solution verifies second-order convergence;
2. a two-material benchmark compares arithmetic and harmonic face averages;
3. a depth comparison of the sparse direct solver against stationary point
   iterators (red-black Gauss-Seidel and optimal-omega SOR) at a matched
   scaled residual of 1e-10, on the same smooth systems;
4. a matched sparse-direct versus unpreconditioned-CG comparison measures
   solve work and error on identical smooth systems;
5. coefficient contrast and fixed-contrast mesh refinement measure solver
   difficulty, while independent forcing and algebraic checks separate errors.

The matrix assembly is fully vectorised (NumPy array operations; no per-node
Python loops), per the brief's vectorisation requirement. A scalar-loop
reference implementation is kept in `code/smoke_test.py` as a regression
test: it verifies that the vectorised assembly reproduces the original
matrix and right-hand side bit-for-bit, and checks the red-black iterator
against the direct solve.

Code-only self-checks (not additional report experiments) use a hand-calculated
variable-coefficient boundary row and the course-bank P2 nonzero-Dirichlet
exact polynomial. A five-tolerance CG scan supports the direct--CG comparison.
Their unrounded data are saved
in `results/hand_checked_row.csv`, `results/nonzero_dirichlet_check.csv`,
and `results/tolerance_sweep.csv`.

## Run in VS Code

Open this folder in VS Code, select the same Python environment used for
MTH321, and run:

```bash
python -m pip install -r requirements.txt
python code/run_all.py
```

For the recorded Python 3.12 reference environment, use
`requirements-reproduce.txt` instead of `requirements.txt` to pin the three
top-level package versions. On a different Python version (for example the
course's Python 3.10 setup), keep the compatible ranges in `requirements.txt`
and compare errors, rates, and correctly rounded table values; raw floating
point residuals and wall times may differ slightly by platform.

The script creates all figures in `figures/` and all numerical tables in
`results/`. It also refreshes the LaTeX macros and table rows imported by the
report.

Compile the report after running the experiments:

```bash
pdflatex main.tex
pdflatex main.tex
```

After a complete run, refresh only the LaTeX tables and numerical macros from
the existing CSV records with:

```bash
python code/run_all.py --report-only
```

## Audit checks

- The matrix is assembled in COO format and converted once to CSR.
- Adjacent rows share one face coefficient, preserving symmetry.
- Dirichlet values are eliminated and moved to the right-hand side.
- Algebraic residuals are reported separately from solution errors.
- `code/smoke_test.py` regression-tests the vectorised assembly against a
  scalar-loop reference (bitwise-identical matrix and right-hand side) and
  checks the red-black iterators against the direct solve.
- Generated numerical macros and tables come from CSV records. The report also
  quotes a few values from those records for interpretation; regenerate and
  verify them if the experimental settings change.
- The direct/CG cost table excludes assembly; its three-repeat median timings
  are machine-dependent. Exit flags and unrounded residuals are in
  `results/solver_cost_comparison.csv`.
- The direct-versus-Gauss-Seidel/SOR depth table drives every iterator to the
  same scaled residual target (1e-10) with a residual stopping rule; a row
  that hits the iteration cap records `info = 1` instead of pretending to
  converge. Unrounded data are in
  `results/stationary_iterator_comparison.csv`.
- `--report-only` refreshes tables but preserves the environment record of the
  last full numerical run.
- Timings can change across machines even when errors and iteration counts
  reproduce; `results/environment.json` records versions from the full run.
- Before submission, each team member should reproduce at least one stated
  result and complete their own contribution and AI-audit records. These
  human sign-offs are not generated by the script.

## Files

- `code/run_all.py`: solver, experiments, plots, and report-table generation.
- `main.tex`: report following the Project 2 brief and Direction 3 requirements.
- `requirements-reproduce.txt`: recorded top-level reference versions;
  `results/environment.json` records the full run platform and Python version.
- `results/*.csv`: machine-readable numerical evidence.
- `results/*.tex`: generated values imported into the report.
- `figures/*.png`: generated figures.
